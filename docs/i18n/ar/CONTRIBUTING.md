# المساهمة في مصدر مفتوح المقبض المتوازي

شكراً على اهتمامكم بالمساهمة في هذا المشروع! نرحب بالمساهمات من مجتمع الروبوتات

<a id="ways-to-contribute"></a>
## طرق المساهمة

<a id="-bug-reports"></a>
### ⁇  تقارير الحشرات
- استخدم متابعة قضايا GitHub
- إضافة خطوات التكاثر المفصلة
- توفير معلومات عن النظام (OS، Python النسخة، نموذج الخدمات)
- ربط السجلات أو رسائل الخطأ

<a id="-feature-requests"></a>
### ⁇  طلبات الميزات
- تحقق من القضايا الموجودة أولاً
- وصف حالة الاستخدام بوضوح
- النظر في تعقيد التنفيذ
- مناقشة مع الحافظين قبل التغييرات الكبيرة

<a id="-code-contributions"></a>
### ⁇  مساهمات الرمز
- أفرق مخزن الخزانة
- إنشاء فرع ميزة
- اتباع معايير التشفير
- إضافة الاختبارات عند الاقتضاء
- تحديث الوثائق

<a id="-documentation"></a>
### ⁇  الوثائق
- تحسين الوثائق الموجودة
- إضافة أمثلة الاستخدام
- إعداد دروس أو دليل
- إصلاح أخطاء النسخة أو تفسيرات غير واضحة

<a id="-hardware-improvements"></a>
### ⁇ ️ تحسينات في الأجهزة
- تعديلات التصميم أو تحسينات
- اقتراحات الأجزاء البديلة
- التوافق الخادم الجديد
- التحسينات الميكانيكية

<a id="development-setup"></a>
## إعداد التطوير

1. **استنساخ مخزن**
   ```bash
   git clone https://github.com/your-org/parallel-gripper.git
   cd parallel-gripper
   ```

2. **تثبيت الاعتمادات**
   ```bash
   pip install -r software/python/requirements.txt
   ```

3. **التثبيت STServo SDK**
   ```bash
   git clone https://github.com/FEETECH-RC/STServo_SDK_Python.git
   cp -r STServo_SDK_Python/STservo_sdk ./software/python/
   ```

<a id="coding-standards"></a>
## معايير التشفير

<a id="python-code"></a>
### Python الرمز
- اتبع دليل نمط PEP 8
- استخدم إشارات النموذج عند الاقتضاء
- إضافة سلسلة الوثائق إلى جميع الوظائف / الفئات
- أقصى طول الخط: 88 حرفًا
- استخدم أسماء المتغيرات ذات معنى

<a id="documentation"></a>
### الوثائق
- استخدم شكل Markdown
- إضافة أمثلة على الرمز
- حافظ على اللغة واضحة وموجزة
- تحديث README إذا لزم الأمر

<a id="3d-models"></a>
### 3D النماذج
- توفير ملفات STL في تنسيق ثنائي
- إدراج ملفات المصدر إذا كان ذلك ممكناً (STEP، Fusion 360، إلخ.)
- طباعة الاختبار قبل الإرسال
- إعدادات طباعة الوثائق

<a id="pull-request-process"></a>
## عملية طلب السحب

1. **قبل البدء**
   - تحقق من القضايا الحالية والعلاقات العامة
   - مناقشة التغييرات الرئيسية أولاً
   - تأكد من أنك تستطيع اختبار التغييرات

2. **تغييرات**
   - إعداد اسم فرع تصريفي
   - اجعل الالتزامات الذرية مع رسائل واضحة
   - اختبر تغييراتك جيداً
   - تحديث الوثائق حسب الحاجة

3. **تقديم العلاقات العامة**
   - ملء نموذج العلاقات العامة
   - القضايا المتعلقة بالصلة
   - إعطاء وصف واضح للتغييرات
   - إضافة معلومات عن الاختبار

4. **عملية المراجعة**
   - ردود الفعل من مراجعي العناوين
   - حافظ على المناقشات البناءة
   - كن صبورا مع عملية المراجعة

<a id="testing-guidelines"></a>
## إرشادات الاختبار

<a id="software-testing"></a>
### اختبار البرمجيات
- اختبار إعدادات الأجهزة الخاصة بك
- التحقق من مطابقة متعددة المنصات
- تحقق من معالجة الأخطاء
- قضايا الحافة الاختبارية

<a id="hardware-testing"></a>
### اختبار الأجهزة
- التحقق من أن الطابعات 3D تعمل بشكل صحيح
- إجراءات تجميع الاختبار
- تحقق من التسامح الميكانيكي
- التحقق من الصلاحية مع مواد مختلفة

<a id="communication"></a>
## التواصل

<a id="channels"></a>
### القنوات
- قضايا GitHub: تقارير الأخطاء ، طلبات الميزات
- المناقشات على GitHub: أسئلة عامة وأفكار
- طلبات السحب: مراجعة الشفرة، مناقشة تقنية

<a id="guidelines"></a>
### المبادئ التوجيهية
- كن واحتراميا وبناءا
- البحث قبل النشر
- إعطاء السياق والتفاصيل
- ساعد الآخرين عندما يكون ذلك ممكناً

المعلومات
