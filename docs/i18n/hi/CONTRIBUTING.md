# ओपन सोर्स समानांतर ग्रिपर में योगदान

इस परियोजना में योगदान देने में आपकी रुचि के लिए धन्यवाद! हम रोबोटिक्स समुदाय के योगदान का स्वागत करते हैं।

<a id="ways-to-contribute"></a>
## योगदान करने के तरीके

<a id="-bug-reports"></a>
### ⁇  बग रिपोर्ट
- GitHub समस्या ट्रैकर का उपयोग करें
- विस्तृत प्रजनन चरणों को शामिल करें
- सिस्टम जानकारी (OS, Python संस्करण, सर्वो मॉडल)
- लॉग या त्रुटि संदेश संलग्न करें

<a id="-feature-requests"></a>
### ⁇  विशेषता अनुरोध
- पहले मौजूदा मुद्दों की जांच करें
- उपयोग के मामले का स्पष्ट रूप से वर्णन करें
- कार्यान्वयन की जटिलता पर विचार करें
- बड़े बदलावों से पहले रखरखावकर्ताओं के साथ चर्चा करें

<a id="-code-contributions"></a>
### ⁇  कोड योगदान
- भंडारण को फोर्क करें
- एक विशेषता शाखा बनाएं
- कोडिंग मानकों का पालन करना
- आवश्यकतानुसार परीक्षण जोड़ें
- अद्यतन प्रलेखन

<a id="-documentation"></a>
### ⁇  प्रलेखन
- मौजूदा प्रलेखन में सुधार
- उपयोग के उदाहरण जोड़ें
- ट्यूटोरियल या गाइड बनाएं
- टाइपिंग त्रुटियों या अस्पष्ट व्याख्याओं को ठीक करें

<a id="-hardware-improvements"></a>
### ⁇ ️ हार्डवेयर में सुधार
- डिजाइन संशोधन या सुधार
- वैकल्पिक भाग सुझाव
- नई सर्वो संगतता
- यांत्रिक अनुकूलन

<a id="development-setup"></a>
## विकास सेटअप

1. **भंडार को क्लोन करें**
   ```bash
   git clone https://github.com/your-org/parallel-gripper.git
   cd parallel-gripper
   ```

2. **निर्भरताएँ स्थापित करें**
   ```bash
   pip install -r software/python/requirements.txt
   ```

3. **स्थापित करें STServo एसडीके**
   ```bash
   git clone https://github.com/FEETECH-RC/STServo_SDK_Python.git
   cp -r STServo_SDK_Python/STservo_sdk ./software/python/
   ```

<a id="coding-standards"></a>
## कोडिंग मानक

<a id="python-code"></a>
### Python कोड
- पीईपी 8 शैली गाइड का पालन करें
- यदि उपयुक्त हो तो टाइप सुझावों का प्रयोग करें
- सभी कार्यों/वर्गों में डॉकस्ट्रिंग जोड़ें
- अधिकतम रेखा लंबाईः 88 वर्ण
- सार्थक चर नामों का उपयोग करें

<a id="documentation"></a>
### प्रलेखन
- मार्कडाउन प्रारूप का उपयोग करें
- कोड उदाहरण शामिल करें
- भाषा को स्पष्ट और संक्षिप्त रखें
- यदि आवश्यक हो तो README को अपडेट करें

<a id="3d-models"></a>
### 3 डी मॉडल
- बाइनरी प्रारूप में STL फ़ाइलें प्रदान करें
- यदि संभव हो तो स्रोत फ़ाइलों को शामिल करें (STEP, Fusion 360, आदि)
- प्रस्तुत करने से पहले परीक्षण प्रिंट
- दस्तावेज़ प्रिंट सेटिंग्स

<a id="pull-request-process"></a>
## खींचें अनुरोध प्रक्रिया

1. **शुरू करने से पहले**
   - मौजूदा मुद्दों और जनसंपर्क की जांच करें
   - सबसे पहले प्रमुख बदलावों पर चर्चा करें
   - सुनिश्चित करें कि आप अपने परिवर्तनों का परीक्षण कर सकते हैं

2. **बदलाव करना**
   - वर्णनात्मक शाखा नाम बनाएं
   - स्पष्ट संदेशों के साथ परमाणु प्रतिबद्धताएं करें
   - अपने बदलावों की पूरी तरह जाँच करें
   - आवश्यकतानुसार प्रलेखन को अद्यतन करें

3. **जनसंपर्क प्रस्तुत करना**
   - PR टेम्पलेट भरें
   - लिंक से संबंधित मुद्दे
   - परिवर्तनों का स्पष्ट विवरण प्रदान करें
   - परीक्षण की जानकारी शामिल करें

4. **समीक्षा प्रक्रिया**
   - पता समीक्षक की प्रतिक्रिया
   - बातचीत को रचनात्मक बनाए रखें
   - समीक्षा प्रक्रिया के साथ धैर्य रखें

<a id="testing-guidelines"></a>
## परीक्षण दिशानिर्देश

<a id="software-testing"></a>
### सॉफ्टवेयर परीक्षण
- अपने हार्डवेयर सेटअप पर परीक्षण
- क्रॉस-प्लेटफॉर्म संगतता की जांच करें
- त्रुटि प्रसंस्करण की जांच करें
- परीक्षण किनारे के मामले

<a id="hardware-testing"></a>
### हार्डवेयर परीक्षण
- 3 डी प्रिंट सही ढंग से काम करते हैं की पुष्टि करें
- परीक्षण इकट्ठा प्रक्रियाएँ
- यांत्रिक सहिष्णुता की जांच करें
- विभिन्न सामग्रियों के साथ मान्य करें
