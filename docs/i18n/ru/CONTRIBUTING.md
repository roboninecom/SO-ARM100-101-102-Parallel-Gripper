# Вклад в открытый источник параллельный захват

Спасибо за вашу заинтересованность в этом проекте! Мы приветствуем вклад робототехники.

<a id="ways-to-contribute"></a>
## Способы внести свой вклад

<a id="-bug-reports"></a>
### ⁇  Отчеты о насекомых
- Используйте отслеживающий проблемы GitHub
- Включить подробные шаги воспроизводства
- Предоставлять информацию о системе (OS, Python версия, сервомодель)
- Прикрепление журналов или сообщений об ошибках

<a id="-feature-requests"></a>
### ⁇  Просьбы о возможностях
- Сначала проверьте существующие проблемы
- Опишите случай использования четко
- Учитывать сложность реализации
- Обсудите с подрядчиками перед большими изменениями.

<a id="-code-contributions"></a>
### ⁇  Вкладные коды
- Развертывать хранилище
- Создать ветку функций
- Соблюдение стандартов кодирования
- При необходимости добавить испытания
- Обновление документации

<a id="-documentation"></a>
### ⁇  Документация
- Улучшение существующей документации
- Добавить примеры использования
- Создать учебные пособия или руководства
- Исправить ошибки в написании или неясное объяснение

<a id="-hardware-improvements"></a>
### ⁇ ️ Улучшение оборудования
- Изменения или улучшения конструкции
- Предложения альтернативных частей
- Новая сервосовместимость
- Механические оптимизации

<a id="development-setup"></a>
## Развитие

1. **Клонировать хранилище**
   ```bash
   git clone https://github.com/your-org/parallel-gripper.git
   cd parallel-gripper
   ```

2. **Установка зависимостей**
   ```bash
   pip install -r software/python/requirements.txt
   ```

3. **Установка STServo SDK**
   ```bash
   git clone https://github.com/FEETECH-RC/STServo_SDK_Python.git
   cp -r STServo_SDK_Python/STservo_sdk ./software/python/
   ```

<a id="coding-standards"></a>
## Стандарты кодирования

<a id="python-code"></a>
### Python Код
- Следуйте руководству по стилю PEP 8
- При необходимости используйте указания на тип
- Добавить строки документов ко всем функциям/классам
- Максимальная длина строки: 88 символов
- Используйте значимые переменные

<a id="documentation"></a>
### Документация
- Используйте формат Markdown
- Включить примеры кодов
- Сохраняйте четкий и краткий язык
- При необходимости обновление README

<a id="3d-models"></a>
### 3D-модели
- Предоставлять файлы STL в бинарном формате
- Включить исходные файлы, если это возможно (STEP, Fusion 360, и т.д.)
- Испытательный отпечаток перед подачей
- Настройки печати документа

<a id="pull-request-process"></a>
## Процесс обращения

1. **Перед началом**
   - Проверяйте существующие проблемы и PR
   - Сначала обсудите основные изменения
   - Убедитесь, что вы можете проверить свои изменения

2. **Изменения**
   - Создать описательное название филиала
   - Сделать атомные обязательства с ясными сообщениями
   - Испытывайте свои изменения тщательно
   - Обновление документации по мере необходимости

3. **Подача ПР**
   - Заполните шаблон PR
   - Вопросы, связанные с линком
   - Укажите четкое описание изменений
   - Включить информацию о тестировании

4. **Процесс пересмотра**
   - Отзывы рецензентов адресов
   - Сохраняйте конструктивные разговоры
   - Будьте терпеливы в процессе обзора
